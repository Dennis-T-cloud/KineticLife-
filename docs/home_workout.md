# Home Workout Module

> Last updated: 2026-05-30
> Branch: `feature-homeworkout`

The Home Workout module is the **third primary entry point** on the Dashboard, accessible via the "Home Mode" bento card. It is a fully isolated, gamified workout flow that reuses the existing ESP32 sensor pipeline and DTW analysis engine without modifying any shared infrastructure.

---

## Architecture

The module follows a **Container Isolation Pattern**: a single `HomeWorkoutContainer` component manages all sub-screens and is mounted as the `"home_workout"` screen in the global router. State persists in the parent via `homeWorkoutCtx` so it survives screen transitions to live exercise and back.

```text
Dashboard → "Home Mode" bento card
  └─ home_workout screen (HomeWorkoutContainer)
       ├─ select          → Route selection + Kini AI character (Avocado Lottie)
       ├─ map             → Quest node path + Kini bubble + Avocado Lottie
       ├─ set_rest        → Inter-set rest (15 s countdown, Set_clear → squrt_walking)
       ├─ exercise_done   → All sets complete (path_clear, avg DTW, next exercise)
       ├─ cardio_preview  → Pre-cardio animation preview (lower route only)
       ├─ cardio          → CardioCountdownScreen (30 s, exercise-specific Lottie)
       ├─ between         → Kini encouragement + blue_jumping between exercises
       └─ reward          → Quest complete (cheering_ribbons → Trophy, muscle heatmap)
```

Live exercise uses the global `"live"` screen with `homeMode=true` and `targetReps` set; on finish it returns directly to `home_workout` (bypasses the analysis screen).

**Shared infrastructure (read-only):**

- ESP32 connection via `iotConnRef` — same connection as gym mode
- DTW engine — full real-time analysis, unchanged
- `muscleStatus` store — updated on workout completion

## Routes

Two static routes are hardcoded in `HOME_ROUTES`. Each has two DTW exercises followed by a 30-second cardio step.

| Route ID | Display Name   | Exercises                              | Cardio         | Accent CSS var |
| -------- | -------------- | -------------------------------------- | -------------- | -------------- |
| `upper`  | APEX PROTOCOL  | Both-Arms Bicep Curl, Lateral Raise    | Jumping Jacks  | `--hw-a`       |
| `lower`  | FORGE PROTOCOL | Bodyweight Squat, Deadlift             | Squat Kicks    | `--hw-b`       |

All exercises: **3 sets × 6 reps**. Cardio: **30 seconds**.

Each route has a `varKey` field (`"a"` or `"b"`) used for CSS custom property resolution throughout the UI (`var(--hw-${varKey})`), ensuring automatic Sunset/Deep Space theme adaptation.

Each cardio step carries:

| Field         | Upper             | Lower              |
| ------------- | ----------------- | ------------------ |
| `lottie`      | `"jumping_jack"`  | `"squat_kick"`     |
| `previewFirst`| —                 | `true`             |

## Screens

### 1. Route Selection (`hwSub: "select"`)

- Kini chat bubble (above) with a **muscle-status-aware greeting** generated by `pickKiniLineForSelection(muscleStatus)`
- Avocado walking Lottie (180 × 180, looping) below the bubble
- Two route cards (themed border + glow via `--hw-${varKey}`)
- Step chips show exercise short code + sets/reps or cardio label

**Kini greeting logic** — `pickKiniLineForSelection(muscleStatus)`:

| Condition | Tone |
| --- | --- |
| No data / all < 8% | "Zero load — start anywhere" (playful) |
| Sore muscle + fresh muscle | Names both explicitly with light teasing |
| Only sore muscles | Suggests controlled reps |
| Lower load > upper by 18%+ | Recommends APEX |
| Upper load > lower by 18%+ | Recommends FORGE |
| Overall > 55% | "High systemic load" warning, cute |
| Balanced | Random positive with mild sarcasm |

### 2. Quest Node Map (`hwSub: "map"`)

- Header: route name (accent color) + tagline
- Kini chat bubble with **route + muscle-aware teasing** from `pickKiniLineForMap(routeId, muscleStatus)` — stored as `ctx.mapKiniLine` at route-selection time
- Avocado walking Lottie (180 × 180, looping)
- Node list: ✓ done / pulsing active / dimmed locked
- **Full row is tappable** (not just the circle); circle glow uses `padding-left: 6px; margin-left: -6px` to prevent clipping

**Kini map logic** — `pickKiniLineForMap(routeId, muscleStatus)`:

| Route load | Tone |
| --- | --- |
| > 70% for chosen group | "Bold/audacious choice" |
| < 20% for chosen group | "Data agrees — perfect call" |
| Normal | Route-personality joke (leg day: "future you already regrets this") |

### 3. Inter-Set Rest (`hwSub: "set_rest"`)

- `Set_clear.json` plays once at the top on enter → replaced by `squrt_walking.json` looping
- DTW score bar + "X of Y" set counter
- Progress dots (completed sets highlighted in `--hw-a`)
- Kini bubble (proud pose) with set-rest phrase
- 15 s countdown — auto-advances to next set; "Start Now" button skips
- Sunset theme: all colors via `--hw-*` CSS custom properties

### 4. Exercise Done (`hwSub: "exercise_done"`)

- `path_clear.json` plays once at top on enter, then disappears
- Average DTW across all sets + per-set breakdown
- Kini advice text (DTW-based: excellent / good / room to improve)
- "Up Next" card showing next exercise or cardio label (uses `step.label`)
- Button: "Next Exercise →" or "Finish Workout →"

### 5. Cardio Preview (`hwSub: "cardio_preview"`)

Lower route only (`previewFirst: true`). Shows the Squat Kicks Lottie playing **once** at full size. "Let's Go" button unlocks after animation completes. Then transitions to `"cardio"`.

### 6. Cardio Countdown (`hwSub: "cardio"`)

Component: `CardioCountdownScreen`

**Upper route (Jumping Jacks):** Enters in **demo phase** — Lottie plays once at full size (timer paused), then timer starts and Lottie loops at reduced size.

**Lower route (Squat Kicks):** After preview screen, enters directly in active phase with Lottie looping.

If no exercise-specific Lottie is available, falls back to the original CSS stick figure.

- Movement detection: polls `iotConnRef.current.lastFrame` every 200 ms; pauses timer after 1.8 s stillness
- Milestone phrases at 85 / 65 / 50 / 30 / 15 / 5 % remaining, color shifts cool → warm
- Header uses `step.label` (not hardcoded "Active Burn")

### 7. Between Exercises (`hwSub: "between"`)

- Kini bubble (proud pose) with between-exercise phrase
- `blue_jumping.json` Lottie looping (110 × 110) as celebration visual
- "Up Next" card
- Button label uses `step.label` for cardio steps

### 8. Reward Screen (`hwSub: "reward"`)

Extracted to `HomeRewardScreen` component (has its own local `rewardPhase` state).

- Phase 1: `cheering_ribbons.json` plays once
- Phase 2: `Trophy.json` appears and plays once
- "QUEST COMPLETE" gradient title (framer-motion entry)
- Kini celebrate pose + closing phrase
- Stats row: total reps, duration, estimated calories
- Muscle progress bars for route's trained muscles (updates system heatmap)
- "COLLECT REWARD & RETURN" → resets `homeWorkoutCtx`, returns to Dashboard

## LiveScreen — Home Mode Modifications

`LiveScreen` accepts `homeMode` (boolean) and `targetReps` (number). When `homeMode=true`:

- Encouraging word flashes on each rep via `hwWord` state (color tracks intensity cool → hot)
- Word overlay positioned at **bottom** of screen (`align-items: flex-end; padding-bottom: 5.5rem`)
- At `reps >= targetReps`: auto-finish via `autoFinishedRef` + 900 ms delay, calls `onFinish`
- `onFinish` routes to `set_rest` or `exercise_done` depending on set count — skips analysis screen

Word palette:

## Kini AI Character

Component: `KiniAvatar({ pose, size })` — deterministic SVG mascot (no external assets). Used on `set_rest`, `exercise_done`, `between`, and `reward` screens.

| Pose | Screen |
| --- | --- |
| `wave` | (legacy, replaced by Avocado on select/map) |
| `proud` | `set_rest`, `exercise_done`, `between` |
| `celebrate` | `reward` |

The select and map screens use `lottieAvocadoWalking` instead of `KiniAvatar`.

### Kini Phrase System

Phrases are static arrays in `KINI_LINES` (keys: `between`, `cardio`, `reward`, `set_rest`, `exercise_done`). Tone is **playful and lightly teasing** — non-aggressive, cute. Examples:

- `set_rest`: "I'd high-five you but I'm a robot. Imagine it."
- `cardio`: "Just wiggle SOMETHING. I won't tell anyone what it looks like."
- `reward`: "Done! You are now 3×6 reps cooler than you were this morning."

Select and map screens use dynamic generators (`pickKiniLineForSelection`, `pickKiniLineForMap`) that read `muscleStatus` at entry time and produce context-aware phrases with the same playful tone.

## State: `homeWorkoutCtx`

Managed in the root app component. `null` when not in a home workout session.

```js
{
  routeId:      "upper" | "lower",
  hwSub:        "select" | "map" | "set_rest" | "exercise_done" |
                "cardio_preview" | "cardio" | "between" | "reward",
  stepIdx:      number,   // index of current/next step in route.steps
  lastDoneIdx:  number,   // index of step just completed (-1 if none)
  currentSet:   number,   // 1-based set counter
  totalSets:    number,   // from step.sets
  targetReps:   number,   // from step.reps
  setResults:   [{ dtw, reps }],  // per-set results
  lastSetDtw:   number,
  totalReps:    number,   // accumulated across all exercise steps
  startTime:    number,   // Date.now() when route was selected
  kiniLine:     string,   // current phrase for Kini bubble
  mapKiniLine:  string,   // route-specific phrase for map screen
}
```

## Muscle Heatmap Integration

On `handleHomeCardioDone()`, the route's `muscles` object is applied to the global `muscleStatus`:

```js
Object.entries(route.muscles).forEach(([muscle, intensity]) => {
  updated[muscle] = Math.min(1, (updated[muscle] ?? 0) + intensity * 0.15);
});
```

This writes to the same store used by the Profile heatmap and the AI plan generator.

## Adding a New Home Route

1. Add entry to `HOME_ROUTES` with `varKey: "a"` or `"b"` (or extend with a third CSS token)
2. Set `exerciseId` values to existing exercise keys (must have DTW template + live rules)
3. Set `lottie` on cardio step to a key resolvable in `HomeWorkoutContainer.cardioLottie()`
4. Add `previewFirst: true` if a preview screen is desired before cardio
5. Define `muscles` intensities (primary mover = `1.0`)
6. No backend changes required
